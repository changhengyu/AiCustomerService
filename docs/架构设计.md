> 本文档介绍 AI 客服 SaaS 系统的整体架构、关键设计决策、模块间协作关系。

## 1. 整体架构

### 1.1 分层架构

```
┌─────────────────────────────────────────────────┐
│  Presentation Layer (Api / Controllers)         │
│  - AuthController / KnowledgeController         │
│  - ConversationController / WeChatController    │
└────────────┬────────────────────────────────────┘
             │ DI
┌────────────▼────────────────────────────────────┐
│  Application Layer (Services)                   │
│  - AuthService / ConversationService            │
│  - KnowledgeService / CustomerService           │
└────────────┬────────────────────────────────────┘
             │ 依赖接口
┌────────────▼────────────────────────────────────┐
│  Domain Layer (Core / Entities / Interfaces)    │
│  - Tenant / User / Customer / Conversation      │
│  - IAIService / IKnowledgeService / ...        │
└────────────┬────────────────────────────────────┘
             │ 实现接口
┌────────────▼────────────────────────────────────┐
│  Infrastructure Layer                           │
│  - AppDbContext (EF Core + pgvector)            │
│  - TongyiAIService / RedisCacheService         │
│  - Hangfire Jobs / JWT / MultiTenancy           │
└─────────────────────────────────────────────────┘
```

### 1.2 技术选型

| 维度 | 选型 | 理由 |
| --- | --- | --- |
| 后端框架 | .NET 10 | LTS、原生 AOT、高性能、Clean Architecture 友好 |
| ORM | EF Core 10 + Npgsql | 成熟、迁移工具完善、支持 pgvector |
| 向量库 | pgvector | 与 PG 一体化、运维简单、足够 MVP |
| 缓存 | Redis 7 | 业内标准、StackExchange.Redis 库成熟 |
| AI | 通义千问 qwen-plus | 中文最佳、成本可控、兼容 OpenAI 协议 |
| Embedding | text-embedding-v3 | 1024 维、效果好、价格低 |
| 任务调度 | Hangfire | 与 .NET 集成好、可视化 Dashboard |
| 认证 | JWT + Refresh Token | 无状态、易扩展 |
| 前端 | Vue 3 + uni-app | 跨端、组件库丰富、社区大 |

## 2. 核心模块

### 2.1 多租户

#### 设计原则
- 租户隔离粒度：数据库行级（每张业务表都有 `tenant_id`）
- 租户识别：从 JWT 的 `tenant_id` Claim 提取
- 上下文传递：通过 `ITenantContext` 接口（Scoped 生命周期）

#### 实现机制
```csharp
// 1. JWT 颁发时写入 tenant_id
var claims = new List<Claim>
{
    new("tenant_id", user.TenantId.ToString()),
    new(ClaimTypes.Role, user.Role)
};

// 2. TenantContext 从 HttpContext 解析
public Guid? CurrentTenantId => Guid.TryParse(
    _httpContext.User.FindFirst("tenant_id")?.Value, out var id) ? id : null;

// 3. Controller 强制要求
_tenantCtx.RequireTenantId()  // 抛 UnauthorizedException if null
```

#### 跨租户场景
- 后台管理员（`super_admin`）可使用 `OverrideTenant(tenantId)` 临时切换上下文
- 普通用户无法跨租户访问任何数据

### 2.2 RAG 检索

#### 整体流程
```
用户问题
   │
   ▼
HybridRetriever.RetrieveAsync()
   │
   ├──► 向量检索
   │     ├── Embedding API → 1024 维向量
   │     └── pgvector <=> 余弦距离
   │           TopK × 2，过滤 score < 0.45
   │
   ├──► 关键词检索
   │     ├── 提取关键词（去掉停用词）
   │     └── PostgreSQL ILIKE 模糊匹配
   │
   └──► 混合排序
         ├── 向量权重 0.6
         ├── 关键词权重 0.4
         └── Score = 0.6 × vector_rank + 0.4 × keyword_rank
```

#### pgvector 距离函数选择
使用 `<=>`（cosine distance）而非 `<->`（L2 distance）：
- Cosine 对向量长度不敏感（关注方向）
- 适合文本语义相似度

#### 关键设计
- **批量 Embedding**：25 条/批次（API 限额 + 速度平衡）
- **失败重试**：3 次指数退避（2s/4s/8s）
- **降级策略**：Embedding API 失败时降级为关键词检索
- **缓存**：热门问题结果缓存 5 分钟（Redis）

### 2.3 知识库摄取

#### 流水线
```
Upload (multipart)
   │
   ▼
KnowledgeService.UploadAsync()
   ├─► 文件落盘 (uploads/knowledge/{guid}.{ext})
   ├─► 创建 KnowledgeDocument(pending)
   └─► Enqueue<IngestDocumentJob>()
        │
        ▼
IngestDocumentJob.ExecuteAsync()
   ├─► DocumentLoader (PDF/Word/TXT/MD/CSV)
   │     └── 提取纯文本
   ├─► TextCleaner
   │     └── 去除 HTML、控制字符、Markdown
   ├─► TextSplitter
   │     ├── 按段落切分（最大 500 字）
   │     └── 段落过长则按句子滑窗（overlap 80）
   ├─► EmbeddingBatcher
   │     ├── 25 条/批
   │     └── 3 次重试
   ├─► PgVectorStore.AddChunksAsync()
   │     └── 写入 knowledge_chunks
   └─► doc.Status = ready, ChunkCount = N
```

#### 状态机
```
pending ──► processing ──► ready
                  │
                  └────► failed (可重试)
```

#### 任务隔离
- `AutomaticRetry(Attempts = 3, DelaysInSeconds = [30, 60, 120])`
- `DisableConcurrentExecution(600)` 防止同一文档并发摄取
- 失败时标记状态但不抛错，错误信息写入 `doc.ErrorMessage`

### 2.4 微信接入

#### 消息流
```
用户发消息到公众号
   │
   ▼
微信服务器 POST /api/v1/wechat/{appId}
   │
   ▼
WeChatController.Receive
   │
   ▼
WeChatService.HandleMessageAsync()
   │
   ├──► 解析 XML
   ├──► 查找租户（通过 ChannelConfig.AppId）
   ├──► 获取或创建 Customer
   ├──► ConversationService.HandleUserMessageAsync()
   │     └── RAG + AI 回复
   └──► WeChatOfficialClient.SendCustomerTextAsync()
         │
         ▼
      微信服务器 ──► 用户微信
```

#### 多租户路由
通过 `channel_configs` 表存储 `{appId, tenant_id, channel_type}` 映射：
```sql
SELECT tenant_id FROM channel_configs
WHERE channel_type = 'wechat' AND app_id = ?
```

#### 简化加密
当前版本对加密消息不做完整解密（生产建议集成 Senparc.Weixin SDK）：
```csharp
public string DecryptMessage(string encrypted, string signature, ...)
{
    // 简化：实际应使用 AES-256-CBC + PKCS#7
    return encrypted;
}
```

### 2.5 Hangfire 后台任务

#### 任务类型
- `IngestDocumentJob`：文档摄取
- `ReindexTenantJob`：全租户重建

#### 存储
使用 PostgreSQL 作为 Hangfire 存储（`Hangfire.PostgreSql`）：
```csharp
builder.Services.AddHangfire(cfg => cfg
    .UsePostgreSqlStorage(opts => opts.UseNpgsqlConnection(connectionString)));
```

#### Dashboard
开发环境：`/hangfire`（无需鉴权）
生产环境：建议加 BasicAuth 或仅内网访问

### 2.6 认证

#### JWT 结构
```json
{
  "sub": "用户ID",
  "tenant_id": "租户ID",
  "username": "admin",
  "role": "owner",
  "exp": 1234567890
}
```

#### 双 Token 机制
- **Access Token**：短期（720 分钟）
- **Refresh Token**：长期（30 天），存储在 `refresh_tokens` 表
- Access 过期后用 Refresh 获取新 Access
- Refresh Token 轮换（每次刷新撤销旧的）

#### 密码哈希
```csharp
// PBKDF2-SHA256, 100000 迭代, 16 字节 salt
var hash = Rfc2898DeriveBytes.Pbkdf2(
    password, salt, 100_000, HashAlgorithmName.SHA256, 32);
```

## 3. 数据模型

### 3.1 实体关系

```
Tenant (1) ──< (N) User
Tenant (1) ──< (N) Customer
Tenant (1) ──< (N) Conversation
Tenant (1) ──< (N) KnowledgeDocument
Tenant (1) ──< (N) ChannelConfig

Customer (1) ──< (N) Conversation
Conversation (1) ──< (N) Message
KnowledgeDocument (1) ──< (N) KnowledgeChunk
User (1) ──< (N) RefreshToken
Tenant (1) ──< (N) Subscription
```

### 3.2 关键表

#### customers
- `id` (UUID, PK)
- `tenant_id` (UUID, FK, indexed)
- `external_id` (string, indexed) - 微信 openid 等
- `channel_type` (string) - wechat / miniprogram / web
- `intention_score` (int) - 0-100
- `intention_level` (string) - cold / low / medium / high
- `tags` (string[]) - 标签数组
- 唯一索引：`(tenant_id, channel_type, external_id)`

#### knowledge_chunks
- `id` (UUID, PK)
- `tenant_id` (UUID, indexed)
- `document_id` (UUID, FK, indexed)
- `chunk_index` (int)
- `content` (text)
- `embedding` (vector(1024)) - pgvector 向量列
- 索引：`ivfflat` (embedding vector_cosine_ops)

#### conversations
- `id` (UUID, PK)
- `tenant_id` (UUID, indexed)
- `customer_id` (UUID, FK)
- `status` (string) - active / human / closed
- `assigned_to` (UUID, nullable) - 转人工后指派
- `last_message_at` (timestamp, indexed for sorting)

## 4. 性能与扩展

### 4.1 性能目标

| 指标 | 目标 |
| --- | --- |
| API 响应 P95 | < 300ms |
| 聊天响应 P95 | < 3s（含 LLM 调用） |
| 文档摄取 | < 30s / MB |
| 数据库连接池 | 100 |
| Hangfire Worker | 4 workers / 节点 |

### 4.2 缓存策略

- **租户设置**：2 小时（变化少）
- **系统 Prompt**：2 小时
- **热门问题 RAG 结果**：5 分钟
- **Embedding**：不缓存（每个问题不同）

### 4.3 限流

- 登录：5 次/分钟/IP
- 文档上传：20 次/小时/租户
- 聊天：按 plan 限制

### 4.4 水平扩展

API 无状态，可任意横向扩展：
- 多实例 + Nginx 负载均衡
- Hangfire Server 多实例（自动选主）
- PostgreSQL 读写分离（未来）
- Redis Cluster（未来）

## 5. 安全

### 5.1 认证安全
- JWT HS256，密钥 ≥ 32 字符
- HTTPS 强制（生产）
- Refresh Token 一次性（轮换）

### 5.2 数据安全
- 密码 PBKDF2 哈希
- 多租户硬隔离（所有查询带 `tenant_id`）
- 文件上传 MIME 校验 + 扩展名校验

### 5.3 审计
- Serilog 记录所有 API 请求
- 敏感字段（密码、Token）脱敏
- AI 用量审计日志（`ai_usage_logs` 表）
